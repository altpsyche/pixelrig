# PixelRig v0.0.2-alpha

Second alpha of PixelRig, a guides-first animation toolkit for Aseprite. This release is about fixes: it runs on older Aseprite builds, fits the ghost to the whole character, and survives bad data.

## Install

1. Download `pixelrig-v0.0.2-alpha.aseprite-extension` below.
2. Double-click it, or in Aseprite: **Edit > Preferences > Extensions > Add Extension** and pick the file. It replaces the previous version.
3. Open a sprite, then **View > Ghost Reference...**

The `.zip` has the same contents if you prefer to unpack it into your extensions folder by hand.

Tested on a current Aseprite source build (Lua API version 41) and on Aseprite v1.3-rc6 (Lua API 25).

## What changed

- **Works on Aseprite v1.3-rc6.** The previous alpha failed to open there with "Field tab does not exist". Where Aseprite has no dialog tabs, the dialog shows a **Section** picker with short sections that fit the screen; newer Aseprite keeps the tabs. (#40)
- **Fit to art fits the whole character.** Fit and the first-open auto-fit measure the selection, else all visible art layers together, no longer just the active layer (a selected `boots` layer used to size the ghost to the boots). (#42)
- **Your place is kept.** Apply and Remove leave your active sprite, layer and frame where they were, even when the ghost adds frames or another sprite's tab is active. Fit measures only the dialog's own sprite. Apply on a sprite that was closed says so. (#3)
- **Bad data never disables PixelRig.** A clip file with a missing rig, bad channels or bad params is skipped, and the dialog shows a **Skipped** line saying which file and why. Corrupt saved ghost settings fall back to defaults. Dragging a joint the clip has no channel for no longer errors. (#4)
- In the Look tab, **Opacity** and **Show art in preview** now sit above the Colors controls.
- Releases now publish their own notes, and only from a commit on `main` that passes every check. (#10)

## Known limits

- Alpha: only the Run clip ships; walk, idle, jump, attack and hurt come next
- Side view and humanoid only
- Apply still adds frames when the clip has more frames than the range; making that opt-in is planned (#27)
- A fit to art shorter than 8 px can break the Height slider (#44)
- Dialog logic is tested headless through a mock dialog; please report UI issues
